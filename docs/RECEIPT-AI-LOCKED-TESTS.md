# Receipt AI native test dependency lock

This is a **RuFlo Hub** test-only lock for the public immutable Receipt AI source commit
`fa9ff4aecabdaeb05f2be54d4b7d649086d0fdd2`. It is **not** a modification of
`ibboabdoli-ai/Ibbo_Receipt_AI`, the Proffera project or any production dependency.

`locks/receipt-ai/package-lock.json` was generated by npm 11 on a short-lived
GitHub Actions runner from that exact checked-out public source using
`npm install --package-lock-only --ignore-scripts --no-audit --no-fund`.
No install lifecycle scripts ran during lock generation.

The native workflow now checks out the hub and Receipt projects into separate
credential-free folders, verifies the Receipt source exact SHA, copies the reviewed
Hub lock into the Receipt checkout, checks the top-level dependencies and
devDependencies against the immutable external manifest, then uses
`npm ci --ignore-scripts --no-audit --no-fund` before testing, typechecking
and linting. The lock pins transitive dependency versions and integrity hashes.

When Receipt AI changes, generate and independently review a fresh lock tied
to the new approved SHA before changing the workflow. Do not return to
`npm install --no-package-lock` or let floating dependency resolutions run
in ordinary native validation.

This only fixes the existing SonarCloud `githubactions:S8543` issue on the
Hub's Receipt AI workflow; it does not enable Receipt AI operations, install
RuFlo into a production environment, change the Supervisor, or authorize
any deployment.
